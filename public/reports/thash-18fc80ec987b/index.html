KVServe: Service-Aware KV Cache Compression for Communication-Efficient Disaggregated LLM Serving

总结

随着大语言模型（LLM）在生产环境中的广泛部署，分离式推理架构（如 Prefill/Decode 分离和 KV 状态分离）虽然提升了可扩展性和成本效率，但也使 KV cache 成为跨网络和存储边界传输的显式负载，成为端到端延迟的主要瓶颈。现有 KV 压缩方法通常采用静态运行时配置，无法适应生产环境中动态变化的工作负载类型、带宽条件和 SLO/质量预算，导致固定策略在不同场景下可能次优甚至增加延迟。KVServe 提出了首个面向分离式 LLM 服务的服务感知自适应 KV 通信压缩框架，通过统一模块化压缩策略空间、贝叶斯离线 profiling 引擎和服务感知在线控制器，实现了在质量和 SLO 约束下的动态最优压缩策略选择。

As-is: 当前分离式 LLM 服务中，KV cache 跨网络/IO 边界传输成为主要瓶颈——在 10–50 Gbps 带宽下，KV 通信时间占 JCT 的 16%–60%，在远程存储场景下甚至高达 66%。现有 KV 压缩方法（如 CacheGen、KIVI、KVQuant）虽然在特定条件下能将 BF16 KV cache 压缩至 4-bit 或 2-bit，但它们均采用静态配置：固定的变换方式、量化粒度和编解码器。这种静态策略存在两个根本问题：一是不同工作负载（数学推理、代码生成、长文档 QA）对压缩的容忍度差异巨大，同一策略在不同任务上的精度和压缩比表现极不稳定；二是最优策略随有效带宽变化而切换，当带宽超过阈值时，压缩/解压开销不再能被通信节省所抵消，反而导致延迟增加（负优化）。此外，现有方法的代码和参数接口紧耦合，难以复用和组合，且策略空间的组合爆炸使得穷举搜索不可行（约需 1000 GPU 小时）。

To-be: KVServe 将 KV 压缩统一抽象为 Transformer → Quantizer → Codec 的模块化流水线，支持跨方法重组和新组件（如 MixHQ 混合精度头级量化）集成，形成可枚举可扩展的策略空间。通过贝叶斯 Profiling Engine（基于高斯过程的贝叶斯优化 + 双向剪枝 + 早停机制），将离线搜索开销从约 1000 小时降至约 20 小时（50× 减少），并蒸馏出精度-压缩比-延迟三维 Pareto 候选集。在线服务感知控制器结合解析延迟模型（推导带宽阈值条件和分段最优策略，实现 O(1) 决策）和轻量级残差校正 bandit（ε-greedy + EWMA 残差估计 + 安全护栏），在运行时动态选择最优 profile 并纠正离线-在线漂移。集成于 vLLM 0.10.1，在多种数据集、模型、GPU 和网络配置上评估，KVServe 在 PD 分离服务中实现最高 9.13× JCT 加速，在 KV 分离服务中实现最高 32.8× TTFT 降低，同时严格满足 97% 相对精度阈值。

背景

分离式推理架构的兴起

大语言模型的自回归生成特性要求在整个解码过程中维护和反复访问 KV cache。推理过程分为两个阶段：Prefill（预填充）阶段并行计算 prompt 的 KV cache，属于计算密集型；Decode（解码）阶段迭代生成 token 并读取 KV，属于内存密集型。

为提升吞吐量并支持更长上下文，生产服务系统正转向分离式推理架构，主要包括两种设计：

1. Prefill/Decode (PD) 分离：将 prefill 和 decode 部署在不同 GPU 节点上，减少共置争用，支持各阶段独立扩展。Prefill 生成 prompt KV cache 后传输给 decode 节点消费。这种分离通常打破了共享高速互联域（如 InfiniBand），在云环境中以太坊连接的 GPU 节点带宽限制会显著放大 KV 迁移成本。

2. KV 状态分离：将 KV cache 卸载到 CPU/SSD 层或远程 KV 池，支持更长上下文和跨请求复用（如 RAG、多轮对话、模板化请求中的前缀缓存）。但远程读取成为延迟关键路径。

KV 通信成为主导瓶颈

在分离式架构中，KV cache 从 GPU 内部状态变为跨设备传输的 I/O 负载。随着上下文增长，KV cache 体量急剧膨胀——例如 Llama 3.1-70B 在 128K token 时生成 39.06 GB KV cache。论文的端到端实验（Figure 1）量化了这一瓶颈：

在 H100 decode 节点上运行 Llama-3.1 + Qasper，当 prefill 节点带宽为 10–50 Gbps 时，KV 通信时间占 JCT 的 16%–60%。对于 2WikiMQA 数据集，通信占比在 4090 上高达 60%。类似地，在远程存储/KV 池场景下（5–15 Gbps 链路），KV 通信占端到端时间高达 66%。

现有 KV 压缩方法的局限性

现有工作如 CacheGen（BF16→4-bit/2-bit 量化 + 无损编码）、KIVI（固定 2-bit 非对称量化）、KVQuant（混合精度量化）等，虽然能显著减少 KV 体量，但存在两个关键问题：

问题一：最优策略随工作负载变化。 不同任务具有截然不同的请求分布和生成行为，导致 KV cache 的统计特性和可压缩性发生系统性偏移。Figure 3 展示了五种方法在四个数据集上的精度和压缩比表现：

KIVI 在 Qasper 上精度最佳，但在 GSM8K 和 HumanEval 上排名垫底；DuoAttention 在 GSM8K 和 HumanEval 上表现最优，但在 Multi-News 和 Qasper 上表现最差。压缩比同样不稳定——CacheGen 在 Multi-News 上达到 6.20× 最佳压缩比，但在 HumanEval 上仅 3.98×，低于 MixHQ 的 5.36×。

问题二：最优策略随带宽变化，甚至可能损害性能。 KV 延迟由两部分组成：压缩 KV 的通信时间和压缩/解压时间。Figure 4 展示了三种方法在不同带宽下的 KV 延迟：

最优策略随带宽切换：CacheGen 在极低带宽下最优，但随着带宽增加被 MixHQ 超越，再被 KIVI 超越（两个交叉点）。更重要的是，每种 profile 仅在特定带宽区间内有益——当带宽超过阈值（三种方法分别为 50/55/110 Gbps）时，通信节省不再能抵消（解）压缩开销，延迟反而比不压缩更差。

---

问题

KVServe 要解决的核心问题是：在分离式 LLM 服务中，如何在动态变化的服务上下文下，自适应地选择满足质量和 SLO 约束的最优 KV 压缩策略，以最小化端到端延迟。

问题形式化

服务上下文定义为 $c = (w, B, T_{SLO}, q_{min})$，其中：

- $w$：工作负载类别（由上层路由器/分类器提供）

- $B$：当前有效带宽（网络或 I/O goodput 的统一抽象）

- $T_{SLO}$：会话段的延迟预算

- $q_{min}$：最低质量要求

KV 压缩策略（profile）定义为三元组 $p = (cr_p, s_p, q_p)$：

- $cr_p$：压缩比，$cr_p \triangleq V / V_p$（$V$ 为未压缩 KV 总量，$V_p$ 为压缩后大小）

- $s_p$：有效（解）压缩吞吐量，定义为编码和解码吞吐量的调和平均

- $q_p$：工作负载 $w$ 下的质量指标

约束优化目标

段级 JCT 建模为：

$$T_p(c) = T_{model}(w) + \frac{V}{s_p} + \frac{V}{B \cdot cr_p}$$

其中 $T_{model}(w)$ 为与压缩策略无关的模型执行成本，$V/s_p$ 为编码+解码时间，$V/(B \cdot cr_p)$ 为压缩后 KV 的通信时间。

优化问题为：在满足 $T_p(c) \leq T_{SLO}$ 和 $q_p(w) \geq q_{min}$ 的约束下，选择 $p$ 最小化 $T_p(c)$。

三大挑战

1. 策略空间的组合爆炸：从流水线/模块选择到细粒度参数调优，候选数量随自由度指数增长。Figure 5（左）显示，启用细粒度调优后搜索空间迅速膨胀至近 $10^4$ 个候选，每个候选需约 15 分钟的端到端 profiling，穷举搜索需数百 GPU 小时。

2. 延迟-质量权衡缺乏清晰决策原则：即使离线 profiling 将空间压缩为有限候选集，在线选择仍面临固有权衡。Figure 5（右）绘制了 131 个候选的分布——相似质量水平下延迟差异显著，进一步降低延迟往往带来非平凡的质量损失。仅按压缩比或质量排序常导致不可行或次优的 profile。

3. 现有方法紧耦合难以复用组合：现有 KV 压缩方法以紧耦合设计实现，代码和参数接口不兼容，难以拆解为即插即用的组件进行跨方法重组。

解决方案

KVServe 由三个核心组件构成，运行于三个阶段：离线 Profiling、在线选择和运行时服务。Figure 6 展示了整体架构：

1. 模块化策略池

流水线抽象

KVServe 将 KV cache 压缩生命周期形式化为三阶段顺序组合 $B \circ S = C(Q(T(X)))$，如 Figure 7 所示：

- Transformer (T)：预处理阶段，重塑分布以利于下游压缩。模块包括 Delta、Hadamard、Affine 以及 ByPass（跳过）。

- Quantizer (Q)：主要位宽缩减阶段。包含多维度量化方法，支持层级和头级混合精度量化。

- Codec (C)：最终编码阶段，集成 nvCOMP 高性能库支持 BitPacking、熵编码、算术编码等算法。

通过将现有 SOTA 方法分解为原子组件，KVServe 能探索它们的笛卡尔积——例如将 QuaRot 的 transformer 与 CacheGen 的 quantizer 配对，发现协同配置。

新组件：MixHQ（Mixed-Precision Head-Wise Quantization）

论文提出了新的量化组件 MixHQ，将范式从二元剪枝转变为可变精度分配。关键设计是区分 Retrieval Heads（检索头）和 Streaming Heads（流式头）：

- 对 Streaming Heads 施加激进的超低位宽量化（而非丢弃）

- 对 Retrieval Heads 保留高精度，以保护关键长程依赖

该框架与重要性估计的粒度正交，可泛化到层维度（如 PyramidKV，对更深层分配更低位宽）和 token 维度（如 SnapKV，保留 heavy-hitters），将离散剪枝决策转化为连续的精度分配谱。

2. 贝叶斯 Profiling Engine

关键观察

通过经验分析得到两个指导性观察（Figure 8）：

- 观察1（精度评估高成本）：全数据集推理代价过高，但在均匀采样子集上的精度快速稳定，近似全量性能且误差可忽略。

- 观察2（压缩比相对排名稳定性）：尽管绝对压缩比随内容波动，但配置间的相对排名在不同请求间严格不变，确保离线识别的高性能配置可靠地转化为在线最优。

算法设计

将任务形式化为约束黑盒优化：$\max_c CR(c)$ s.t. $Acc(c) \geq Acc_{threshold}$。采用基于高斯过程的贝叶斯优化（而非进化算法或随机搜索），原因在于：(1) 样本效率——高评估成本下最小化迭代次数；(2) 不确定性建模——GP 同时估计均值和方差，支持原则性的探索-利用权衡。

采集函数设计为：

$$\alpha(c) = \underbrace{CR(c) \cdot P(\text{Feasible})}_{\text{Exploitation}} + \underbrace{\lambda_t \cdot \sigma_{norm}(c)}_{\text{Exploration}}$$

其中 $P(\text{Feasible})$ 为满足精度约束的后验概率，$\lambda_t$ 为随迭代衰减的探索权重。

四项关键优化（Algorithm 1）：

1. 异构参数编码：通过 One-Hot 和 Min-Max 缩放将类别和数值变量映射到统一嵌入，确保 GP 核正确度量结构相似性。

2. 探索-利用策略：探索权重 $\lambda_t$ 指数衰减，从全局探索过渡到快速利用。

3. 双向剪枝：利用 CR-Acc 单调性——若不可行则丢弃更高 CR 候选，若可行则丢弃更低 CR 候选。Figure 9 可视化了预测和剪枝过程：

4. 早停机制：连续失败次数 $k_{fail}$ 超限或有效搜索空间耗尽时终止。

效果

对超过 4000 个候选的穷举搜索需约 1000 小时，而算法在不到 80 次迭代（约 20 小时）内收敛，实现 50× 搜索开销减少。

3. 服务感知在线控制器

解析延迟模型

定理 6.1（带宽阈值条件）：对任意 profile $p$，其离线参数确定带宽阈值：

$$B_p^\star = \left(1 - \frac{1}{cr_p}\right) s_p$$

当 $B < B_p^\star$ 时 profile 有益（$T_p(c) < T_0(c)$），否则非有益可在线过滤。该条件独立于 KV 体量 $V$，仅依赖压缩比和（解）压缩吞吐量。

定理 6.2（分段最优策略）：令 $x = 1/B$，$\tilde{T}_p(x) = 1/s_p + (1/cr_p) \cdot x$ 为 $x$ 的线性函数。最小化 $\tilde{T}_p(x)$ 等价于取所有直线的下包络，最优 profile 在 $x$ 上分段常数——存在断点 $0 = x_0 < x_1 < \cdots < x_m$ 使得在每段 $[x_i, x_{i+1})$ 内最优 profile 固定为 $p_i$。

在线决策流程：给定测量带宽 $B$，先用定理 6.1 过滤非有益 profile，再用定理 6.2 查表返回最优 profile 及相邻 profile 作为候选集，实现 O(1) 决策成本。

残差校正 Bandit

解析模型可能因在线漂移（GPU 负载、队列争用、调度开销）而偏离实际。Figure 11 展示了候选集生成和 bandit 校正机制：

候选集构造：以模型最优 profile $p_{b,i}^{model}$ 为中心，加上下包络上 1–2 个相邻 profile：$P_{b,i}^{cand} = \{p_{b,i}^{model}\} \cup \text{Nbr}(p_{b,i}^{model})$，通常仅 2–3 个 profile。

残差学习：对每个候选维护 EWMA 残差估计：

$$\bar{\delta}_{b,i}(p) \leftarrow (1-\alpha)\bar{\delta}_{b,i}(p) + \alpha\delta$$

校正后有效延迟为 $T_p^{eff} = \hat{T}_p(c) + \bar{\delta}_{b,i}(p)$。

选择策略：ε-greedy——以概率 $1-\varepsilon$ 选择满足约束且最小化 $T_p^{eff}$ 的 profile，以概率 $\varepsilon$ 随机探索其余候选。因动作空间至多三个，无需更重的上下文 bandit（如 LinUCB）。

安全护栏：(1) 使用 $\hat{T}_p(c) \leq T_{SLO}$ 作为保守可行性过滤，若可行集为空则回退到默认保守配置；(2) 冷却机制——若某 profile 在最近 $M$ 次使用中超过 $K$ 次 SLO 违规，则在冷却窗口内暂时移除。

该在线学习层开销可忽略：每个请求最多评估 2–3 个候选并更新常数大小状态，不影响 token 级推理延迟。

测试结果

实验设置

- 平台：基于 vLLM 0.10.1 实现，集成 lm-eval-harness 评估在线推理精度影响

- 模型：Qwen2.5-7B-Instruct、Llama-3.1-8B-Instruct、Qwen2.5-32B-Instruct

- 数据集：

- Profiling 数据集：GSM8K（数学）、HumanEval（代码）、Multi-News（摘要）、Qasper（QA）

- 未见数据集：2WikiMQA、HotpotQA（验证泛化能力）

- 硬件：离线 profiling 在 4× A100 (40GB) 上进行，H100 用于解码；prefill 节点覆盖三个层级：

- 消费级（10 Gbps）：2× RTX 4090 (24GB)、2× RTX 5090 (32GB)

- 工作站级（50 Gbps）：2× RTX Pro 6000 (96GB)

- 数据中心级（100 Gbps）：2× H100 (80GB)

- 基线：CacheGen（固定流水线内调优量化粒度）、KIVI（固定 2-bit 非对称量化）、DuoAttention（基于剪枝的 token 丢弃）

- 精度约束：97% 相对精度阈值

端到端性能

跨硬件和工作负载的 JCT 表现（Figure 12）

硬件维度（上行）：KVServe 在所有硬件层级上始终实现最低 JCT，在带宽受限设备上最高达 3.15× 加速。关键发现是静态基线（CacheGen、KIVI）在 Qwen2.5-7B-Instruct 上频繁违反 97% 精度阈值（图中 × 标记），而 KVServe 严格保持精度同时超越它们。

数据集维度（下行）：KVServe 在长上下文任务上实现巨大缩减（HotpotQA 上 9.13×）。在短上下文工作负载（GSM8K、HumanEval）上，基线方法因（解）压缩开销超过通信节省而遭受负优化（JCT 高于 Default），而 KVServe 的服务感知控制器通过理论模型过滤非有益 profile，正确地绕过压缩，使性能收敛到未压缩基线而非退化。

Llama-3.1-8B-Instruct 上最高达 9.13× JCT 加速，Qwen2.5-32B-Instruct 上达 8.82×。

跨带宽的自适应性能（Figure 13）

在 PD 分离场景下，KVServe 在 5–100 Gbps 带宽范围内始终优于所有基线。Llama-3.1-8B-Instruct 上达 5.6× 加速，Qwen2.5-32B-Instruct 上达 9.2×。静态方法在低带宽下可能有效，但在高带宽下因解压瓶颈而性能下降；KVServe 通过带宽阈值条件自动切换策略，在所有带宽区间保持最优。

前缀缓存场景的 TTFT 表现（Figure 14）

在 KV 状态分离的前缀缓存场景下，KVServe 在 2WikiMQA 上实现 32.8× TTFT 降低（SLO=1.5s），在 HotpotQA 上实现 11.8× TTFT 降低（SLO=3.0s）。CacheGen 在部分带宽下表现尚可但波动大，而 KVServe 在全带宽范围内稳定最优。

Pareto 效率

论文验证了离线搜索算法能有效识别平衡高压缩比和严格精度约束的最优压缩流水线。通过贝叶斯优化，从超过 4000 个候选中蒸馏出 3D Pareto 前沿，在 97% 精度约束下，KVServe 识别的配置在压缩比和精度上均优于单一基线方法。MixHQ 组件通过区分 Retrieval/Streaming Heads 的差异化精度分配，在保持精度的同时实现了更高的压缩比。

算法有效性

- 离线搜索：贝叶斯优化 + 双向剪枝 + 早停机制将搜索从约 1000 小时降至约 20 小时（50× 减少），且采样子集上的精度评估可靠地近似全量性能。

- 在线决策：解析模型提供 O(1) 决策的强先验，残差校正 bandit 仅在 2–3 个候选上做微调，安全护栏确保 SLO 不被违反。在带宽波动和系统漂移下，bandit 有效纠正了离线-在线不匹配。

局限性

论文未深入讨论以下方面：

- 工作负载分类器 $w$ 的实现依赖上层路由器，未评估分类错误对策略选择的影响

- 在线 bandit 的探索阶段（ε-greedy）可能引入少量次优决策，虽有安全护栏但仍有 SLO 违规风险

- 离线 profiling 需针对每个模型重新执行（约 20 小时），模型更新时需重新搜索

- 实验中最大模型为 32B，更大规模模型（如 70B+）的扩展性未充分验证

- 跨请求 KV 复用场景下的压缩策略一致性假设可能在多请求并发时面临挑战
